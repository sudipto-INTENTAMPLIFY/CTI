# CyberTech Intelligence — RC11 10/10 Category-Leader Plan

## Goal
Build the October-2026 experience standard for CyberTech Intelligence without unsupported claims, fabricated proof, covert identity inference, or automatic production mutation.

## 10/10 release gates
1. Visual fidelity: approved typography, spacing, motion, hierarchy and responsive behavior verified at desktop/tablet/mobile reference widths.
2. Runtime: all public routes, assets, APIs, forms, calls, chatbot and threat/vendor/content experiences return expected responses with no unexplained blocking console/network failures.
3. Signal-to-SQL: every eligible journey produces stable first-party event IDs, consent state, account/contact correlation, server-side qualification, dedupe, owner routing and downstream attribution.
4. Evidence: every material factual/market/security/customer claim has a source, evidence type, freshness timestamp, owner and status.
5. Threat intelligence: source provenance, freshness and health visible; degraded sources fail safely without inventing data.
6. Trust: public Trust Center with security, privacy, AI-use, methodology, provenance, retention, disclosure, status, subprocessors, accessibility and terms.
7. Search/LLM discovery: canonical non-hash URLs, sitemap, robots, llms.txt, structured data, crawlable page copy and published-content freshness.
8. Security: WAF/rate limits/schema validation/security headers/secret isolation/abuse monitoring verified. No claim of zero attacks; objective is prevention, detection, containment and recovery.
9. Performance: Core Web Vitals target LCP <=2.5s, INP <=200ms, CLS <=0.1 at staging origin on representative mobile and desktop tests.
10. Rollback: immutable release artifact, known-good checkpoint, documented rollback and evidence pack before production approval.

## October 2026 experience target
- Dark premium cybersecurity visual system retained, but density becomes adaptive to intent.
- Persistent command layer: search / ask / navigate / account context / next-best action in one compact interface.
- CyberTech Signal Concierge becomes an evidence-aware assistant: responses are limited to approved site content and evidence-graph records; citations/provenance shown for factual answers.
- Pages use progressive disclosure: decisive executive summary first, deeper operator/research evidence below.
- Intelligence pages expose Fact / Source / Freshness / Interpretation / Commercial implication / Next action as separate UI fields.
- Buyer-state personalization changes CTA and content priority, never factual claims.
- Known-account state is visibly distinguishable from verified person identity; verified identity is distinguishable from marketing permission.
- Mobile-first sticky action rail for high-value actions without obscuring content.
- Device classes: desktop, tablet, phone, large displays and low-width wearable browsers get progressively simplified layouts; no critical action requires hover.
- Reduced-motion preference honored; animations are short, functional and interruptible.

## Category moat
The moat is a compounding evidence-and-outcome graph, not a claim of literal monopoly:
Threat/category evidence -> content/research -> visitor signal -> account context -> verified identity where permitted -> buying-group context -> qualification -> activation -> CRM -> meeting/opportunity -> attribution -> outcome -> learned next-best action.

Each loop improves prioritization, content relevance and source confidence while keeping facts, inferences and recommendations separate.

## No-hallucination policy
A literal 0% hallucination guarantee is not technically defensible. RC11 uses a zero-unsupported-claim policy:
- factual responses require an evidence_graph_id;
- unsupported claims render as unknown/not verified;
- model-generated interpretation is labeled Interpretation;
- commercial recommendation is labeled Recommended action;
- customer/revenue/certification/security claims require human-approved evidence status;
- expired evidence cannot support a live claim;
- retrieval failure never falls back to invented content.

## Monthly evolution model
Monthly automation may measure, detect, propose and prepare a PR. It must not auto-merge or auto-deploy.

Cadence:
Week 1: performance, broken-route, indexation, threat-source-health and security-control audit.
Week 2: signal funnel analysis by page/topic/account/CTA and dead-end detection.
Week 3: evidence freshness review, content gaps, search demand and ICP journey gaps.
Week 4: one bounded RC proposal with tests, screenshots, expected metric, rollback and evidence impact.

Every monthly change requires staging validation and human approval before production.

## Primary scorecard
- Evidence coverage: % of material claims with current approved evidence.
- Signal observability: % of defined events accepted server-side with stable IDs.
- Identity integrity: verified identity transitions with evidence lineage; no inferred identity presented as fact.
- Consent integrity: marketing permission independently tracked and auditable.
- CRM integrity: dedupe/account association/owner routing/retry success.
- Conversion integrity: qualified CTA -> meeting/call/form -> CRM association traceable end-to-end.
- Threat freshness: enabled feed health and latest successful refresh.
- Search discoverability: indexed canonical pages and structured-data validation.
- UX reliability: successful critical journey rate by device/browser.
- Performance: CWV pass rate.

## Production boundary
RC11 is development scope only. No merge to main, production cutover, connector activation, privileged-access change or irreversible write without the required release approval and evidence.
